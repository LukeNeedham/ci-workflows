# The README standard

Every app in [`apps.json`](../apps.json) has a `README.md` at its repo root in the same layout, so any app can be
picked up and understood the same way. The layout lives **here**; the content lives **in each app**, in a
`readme.yml` at its repo root.

## How it works

1. The app has **`readme.yml`**, written by hand ([skeleton](readme-template.yml)): the name, tagline, description,
   features, minimum Android version, where things are, the license, and a few optional parts.
2. [`scripts/generate_readme.py`](../scripts/generate_readme.py) renders **`README.md`** from it in the standard
   layout. The shared parts (the icon, the build and test commands, "Contributing", the links) come from the
   script, so the app writes only what only it knows.
3. The `readme` job of [`android_pr.yml`](../.github/workflows/android_pr.yml) runs the script on every PR, like
   the [app icon](app-icon.md) job, and **commits `README.md` to the PR branch** when it differs.

So: **edit `readme.yml`, never `README.md`** (it carries a "generated" comment and is overwritten). The content is
handwritten; only the layout is generated. When the app changes in a way a reader would notice (a feature, the
requirements, the structure), update `readme.yml` in the same PR.

To change the layout for every app, change the script here: the next PR in each app gets a regenerated README.

## The layout

In this order (the title block and the sections are always there, so they cannot be forgotten):

1. The app's icon (the root `app-icon.png`, [generated by CI](app-icon.md)), its name as the one `#` heading and the tagline.
2. `## Description`
3. `## Features`
4. `## Screenshots`, only when `screenshots` is set
5. `## Getting started as a user`: install from the app hub (AppHub) or the Releases page, then the app's own
   `user.steps`, then the minimum Android version
6. `## Getting started as a developer`: requirements, clone, build and test commands, CI; plus `developer.notes`
7. `## Project structure`: `structure`, optionally `architecture`, and a link to the shared conventions
8. Any `sections` of the app (Privacy, Roadmap, Credits, Known issues), as `## <title>`
9. `## Contributing`
10. `## License`: `license`, with a `LICENSE` file at the repo root; "All rights reserved" if the app is not open source (then no `LICENSE` link is rendered)

## Fields of readme.yml

| Field | Required | Meaning |
|---|---|---|
| `name`, `tagline` | yes | The app's name and one line on what it does |
| `description` | yes | What it is and who it is for; a paragraph or two |
| `features` | yes | List of bullets |
| `screenshots` | no | List of `path` (an image in the repo) and `alt` |
| `user.min-android` | yes | For example `"8.0 (API 26)"` |
| `user.install` | no | Replaces the default first step (install from AppHub or the Releases page), for an app that is not installed that way |
| `user.steps` | no | Steps after installing, such as first-run steps |
| `developer.notes` | no | Anything extra a developer needs (a secret, a local setup step) |
| `structure` | yes | Where things are, one bullet each |
| `architecture` | no | The architecture in a few lines |
| `sections` | no | Extra sections: a list of `title` and `body` |
| `license` | yes | The license name |

Unknown fields are an error, so a typo does not silently drop content. Keep it accurate over long.

## Running it yourself

Not needed, since CI does it, but to see the result before pushing (from the app's repo root):

```
pip install pyyaml
curl -fsSL https://raw.githubusercontent.com/LukeNeedham/ci-workflows/main/scripts/generate_readme.py -o /tmp/generate_readme.py
python3 /tmp/generate_readme.py            # writes README.md
python3 /tmp/generate_readme.py --check    # writes nothing, exits 1 if README.md is out of date
```

## Rollout and reporting

- An app with **no `readme.yml`** gets a warning in its PR build and keeps its current README until it has one.
  The [sync](sync.md) lists such apps (and invalid `readme.yml`s) in its run summary. It never writes a `readme.yml`.
- The managed `CLAUDE.md` block that the sync gives every app tells Claude to write `readme.yml` once from the
  template when it is missing, and afterwards to edit only it. The skill says the same ([skill.md](skill.md)).
- **Forks:** a PR from a fork cannot be committed to, so there the job fails if `README.md` is out of date and says
  to run the script.
